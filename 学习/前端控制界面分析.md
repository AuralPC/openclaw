# OpenClaw 前端控制界面分析

本文档分析 OpenClaw 的前端控制界面（Control UI），包括技术栈、架构设计、核心功能和与后端的通信机制。

## 1. 概览

## 3. 核心组件

### 3.1 主应用组件 (OpenClawApp)

主应用组件是整个 UI 的核心，使用 Lit 的 `@customElement` 装饰器定义：

```typescript
@customElement("openclaw-app")
export class OpenClawApp extends LitElement {
  // 状态管理 - 使用 @state 装饰器实现响应式
  @state() connected = false;
  @state() tab: Tab = "chat";
  @state() chatMessages: unknown[] = [];
  @state() chatLoading = false;
  // ... 更多状态

  // Gateway 客户端
  client: GatewayBrowserClient | null = null;

  // 生命周期方法
  connectedCallback() { /* 组件挂载 */ }
  firstUpdated() { /* 首次渲染后 */ }
  disconnectedCallback() { /* 组件卸载 */ }

  // 渲染方法
  render() {
    return renderApp(this);
  }
}
```

## 5. Gateway 通信

### 5.1 WebSocket 客户端

`GatewayBrowserClient` 是前端与 Gateway 通信的核心类：

```typescript
export class GatewayBrowserClient {
  private ws: WebSocket | null = null;
  private pending = new Map<string, Pending>();

  // 建立连接
  start() { /* ... */ }

  // 断开连接
  stop() { /* ... */ }

  // 发送 RPC 请求
  request<T>(method: string, params?: unknown): Promise<T> {
    const id = generateUUID();
    const frame = { type: "req", id, method, params };
    this.ws.send(JSON.stringify(frame));
    return new Promise((resolve, reject) => {
      this.pending.set(id, { resolve, reject });
    });
  }
}
```

## 6. 认证机制

### 6.1 认证流程

```
┌─────────────────────────────────────────────────────────────────┐
│                       认证流程                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌───────────────────┐                                         │
│  │ 1. 建立 WebSocket │                                         │
│  └─────────┬─────────┘                                         │
│            │                                                    │
│            ↓                                                    │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 2. 接收 connect.challenge 事件                             │ │
│  │    { "event": "connect.challenge", "payload": { "nonce" }} │ │
│  └─────────┬─────────────────────────────────────────────────┘ │
│            │                                                    │
│            ↓                                                    │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 3. 生成设备身份                                            │ │
│  │    • 加载或创建 Ed25519 密钥对                             │ │
│  │    • 使用私钥签名认证载荷                                  │ │
│  │    • 包含: deviceId, clientId, role, scopes, signedAt     │ │
│  └─────────┬─────────────────────────────────────────────────┘ │
│            │                                                    │
│            ↓                                                    │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 4. 发送 connect 请求                                       │ │
│  │    {                                                       │ │
│  │      method: "connect",                                    │ │
│  │      params: {                                             │ │
│  │        client: { id, version, platform, mode },            │ │
│  │        device: { id, publicKey, signature, signedAt },     │ │
│  │        auth: { token, password },                          │ │
│  │        role: "operator",                                   │ │
│  │        scopes: ["operator.admin", ...]                     │ │
│  │      }                                                     │ │
│  │    }                                                       │ │
│  └─────────┬─────────────────────────────────────────────────┘ │
│            │                                                    │
│            ↓                                                    │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │ 5. 接收 hello-ok 响应                                      │ │
│  │    • 存储 deviceToken 到 localStorage                      │ │
│  │    • 后续连接可使用 deviceToken                            │ │
│  └───────────────────────────────────────────────────────────┘ │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 认证方式

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| **Token 认证** | 使用 Gateway 配置的 token | 首次连接、无设备身份时 |
| **Password 认证** | 使用共享密码 | Funnel 公网访问 |
| **设备身份认证** | Ed25519 签名 + deviceToken | 已配对设备 |
| **Tailscale 身份** | Tailscale 用户头 | Tailscale Serve 模式 |

### 6.3 设备配对

```
首次从新设备/浏览器连接：

1. Gateway 返回: "disconnected (1008): pairing required"

2. 用户在命令行批准:
   $ openclaw devices list           # 查看待配对设备
   $ openclaw devices approve <id>   # 批准设备

3. 设备被记住，后续连接自动认证

注意：
• localhost (127.0.0.1) 自动批准
• 远程连接需要显式批准
• 清除浏览器数据需要重新配对
```

## 12. 总结

### 12.1 技术特点

| 特点 | 说明 |
|------|------|
| **轻量级** | 使用 Lit Web Components，无重型框架 |
| **实时通信** | WebSocket 双向通信，支持流式输出 |
| **安全认证** | Ed25519 设备身份 + Token/Password |
| **响应式** | 基于 Lit 的 @state 状态管理 |
| **可扩展** | 模块化架构，易于添加新功能 |

### 12.2 与多用户平台的关系

```
┌─────────────────────────────────────────────────────────────────┐
│                Control UI 在多用户场景中的角色                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原生设计：                                                     │
│  • 单用户个人助手的管理界面                                     │
│  • 连接到单个 Gateway 实例                                      │
│  • 管理所有渠道和配置                                           │
│                                                                 │
│  多用户适配：                                                   │
│  • 每个用户 Pod 有独立的 Gateway + Control UI                   │
│  • 用户只能访问自己的 Control UI                                │
│  • 需要在 K8s 层面做用户认证和路由                              │
│                                                                 │
│  可能的改造方向：                                               │
│  • 添加用户级别的登录界面                                       │
│  • 支持多租户 Gateway 连接                                      │
│  • 添加用户权限管理界面                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
