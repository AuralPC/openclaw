# 多会话场景下的沙箱隔离策略分析

## 🎯 你的场景：一个用户，多个对话

假设你有这样的使用模式：
```
用户 Alice
├─ 对话 1：帮我写 Python 脚本
├─ 对话 2：分析这个日志文件
├─ 对话 3：查询天气信息
└─ 对话 4：继续修改对话 1 的脚本
```

### 三种隔离策略对比

#### 策略 A：per-session（每个对话独立容器）

```
对话 1 → 容器 A  [Python 脚本 script.py]
对话 2 → 容器 B  [日志文件 log.txt]
对话 3 → 容器 C  [天气数据]
对话 4 → 容器 D  [❌ 找不到 script.py！]
```

**配置**：
```yaml
sandbox:
  scope: "per-session"
```

**优点**：
- ✅ **最强隔离**：每个对话完全独立，互不影响
- ✅ **最安全**：一个对话的问题不会影响其他对话
- ✅ **易清理**：对话结束就删除，不留痕迹

**缺点**：
- ❌ **无法共享文件**：对话 4 无法访问对话 1 创建的 script.py
- ❌ **重复安装**：每个对话都要重新安装依赖
- ❌ **性能最差**：每次都要创建新容器（2-5 秒延迟）
- ❌ **无法延续工作**：无法在新对话中继续之前的工作

**适用场景**：
- 🔒 处理敏感数据（每次都清理干净）
- 🧪 测试不同配置（互不干扰）
- 👥 多用户共享（用户间完全隔离）

---

#### 策略 B：per-agent（每个 Agent 一个容器）

```
对话 1 → 容器 X  [创建 script.py]
对话 2 → 容器 X  [创建 log.txt，script.py 还在！]
对话 3 → 容器 X  [天气数据，前面的文件都在]
对话 4 → 容器 X  [✅ 可以修改 script.py！]
```

**配置**：
```yaml
sandbox:
  scope: "per-agent"
```

**优点**：
- ✅ **文件共享**：所有对话共享同一个工作空间
- ✅ **工作延续**：可以在新对话中继续之前的工作
- ✅ **性能好**：容器复用，几乎无延迟
- ✅ **依赖持久**：安装一次，所有对话都能用

**缺点**：
- ❌ **安全性降低**：不同对话可以访问彼此的文件
- ❌ **状态污染**：一个对话的修改会影响其他对话
- ❌ **难以清理**：需要手动清理文件

**适用场景**：
- 🛠️ **持续开发**：多个对话协作完成一个项目
- 📝 **工作延续**：需要在对话间保持上下文
- 🏃 **性能优先**：频繁交互，不能有延迟

---

#### 策略 C：shared（所有 Agent 共享一个容器）

```
Agent A 的对话 1 → 容器 SHARED
Agent A 的对话 2 → 容器 SHARED  } 所有对话
Agent B 的对话 1 → 容器 SHARED  } 都在同一个
Agent B 的对话 2 → 容器 SHARED  } 容器里！
```

**配置**：
```yaml
sandbox:
  scope: "shared"
```

**优点**：
- ✅ **最快**：容器永远存在，零延迟
- ✅ **跨 Agent 共享**：不同 Agent 可以协作

**缺点**：
- ❌ **隔离性最差**：所有对话混在一起
- ❌ **容易冲突**：文件名冲突、环境污染
- ❌ **难以调试**：分不清哪个对话创建的文件

**适用场景**：
- 🏢 **单一项目**：所有对话都在处理同一个项目
- ⚡ **极致性能**：延迟绝对不能接受

---

## 💡 推荐策略：根据使用模式选择

### 场景 1：你是唯一用户，需要持续工作

**推荐**：`per-agent` + 部分隔离

```yaml
sandbox:
  mode: "non-main"        # 主对话窗口免沙箱，最快
  scope: "per-agent"      # 其他渠道用沙箱，共享容器
  workspaceAccess: "rw"   # 读写访问，方便工作
```

**逻辑**：
- 你直接对话时 → 不用沙箱（最快）
- Telegram/Discord 等 → 用沙箱（安全）
- 同一个 Agent 的对话 → 共享容器（可以延续工作）

**例子**：
```
你在主窗口：
  对话 1："写个 Python 脚本" → 直接在本地执行，创建 script.py

你在 Telegram：
  对话 2："帮我测试这个脚本" → 沙箱执行，可以访问 script.py（rw 模式）
  对话 3："修改脚本添加日志" → 同一个容器，修改会保留
```

---

### 场景 2：你是唯一用户，每个对话独立任务

**推荐**：`per-session` + 必要时共享

```yaml
sandbox:
  mode: "non-main"
  scope: "per-session"    # 每个对话独立
  workspaceAccess: "ro"   # 只读访问主工作区
```

**逻辑**：
- 每个对话独立隔离
- 但都可以只读访问你的项目文件夹
- 如果需要保留结果，在主对话中整理

**例子**：
```
对话 1："分析 data.csv"
  → 独立容器 A，可以读取 data.csv（ro），结果在容器内

对话 2："测试这段代码"
  → 独立容器 B，可以读取代码文件（ro），测试结果隔离

需要结果时，在主对话（无沙箱）中整理文件
```

---

### 场景 3：多用户共享，完全不信任

**推荐**：`per-session` + 严格隔离

```yaml
sandbox:
  mode: "on"              # 强制沙箱
  scope: "per-session"    # 每个会话独立
  workspaceAccess: "none" # 完全隔离
  docker:
    readOnlyRoot: true
    network: "none"
    memory: "256m"
```

**逻辑**：
- 绝对隔离，无法互相访问
- 每次对话结束就清理
- 资源严格限制

---

## 🔄 如何在对话间共享数据？

既然 `per-session` 会隔离，那怎么共享数据呢？

### 方法 1：使用主工作区（推荐）

```yaml
sandbox:
  scope: "per-session"
  workspaceAccess: "rw"   # 读写访问主工作区
```

**工作原理**：
```
主工作区（你的项目文件夹）
    ↓ 映射到容器
容器 A → /workspace → 主工作区  }
容器 B → /workspace → 主工作区  } 通过主工作区共享
容器 C → /workspace → 主工作区  }
```

**效果**：
- 所有容器都能访问 `/workspace`
- `/workspace` 实际映射到你的项目文件夹
- 通过主工作区实现数据共享

**例子**：
```
对话 1 在容器 A：
  "创建 script.py" → 写入 /workspace/script.py
                    → 实际保存到你的项目文件夹

对话 2 在容器 B：
  "修改 script.py" → 读取 /workspace/script.py
                    → 能看到对话 1 创建的文件！
```

---

### 方法 2：使用 Docker Volume（高级）

虽然 OpenClaw 默认没有直接配置 volume，但你可以通过自定义配置：

```yaml
sandbox:
  scope: "per-session"
  docker:
    binds:
      - "/path/to/shared:/shared:rw"  # 共享目录
```

**效果**：
- 所有容器挂载同一个共享目录
- 数据持久化在宿主机
- 独立于主工作区

---

### 方法 3：通过 Agent 的内存系统（最优雅）

OpenClaw 有一个 **Memory 系统**，可以跨对话共享信息：

```
对话 1："记住：项目名称是 MyProject"
  → 保存到 Memory 系统

对话 2："项目名称是什么？"
  → 从 Memory 读取："MyProject"
```

**优点**：
- ✅ 不依赖文件系统
- ✅ 结构化存储
- ✅ 跨容器、跨对话
- ✅ 支持向量搜索（相关性检索）

**实现**：
- 位于 [src/memory/](../src/memory/)
- 使用 SQLite + sqlite-vec
- 可选 LanceDB 后端（扩展）

---

## 📊 最终推荐矩阵

| 你的需求 | 推荐配置 | Scope | Workspace | 原因 |
|---------|---------|-------|-----------|------|
| **个人使用，持续工作** | 混合模式 | per-agent | rw | 平衡性能和便利 |
| **个人使用，独立任务** | 轻度隔离 | per-session | ro | 隔离但可访问文件 |
| **开发调试** | 关闭沙箱 | N/A | N/A | 最快，完全访问 |
| **多用户，轻度信任** | 用户隔离 | per-agent | ro | 用户间隔离，对话间共享 |
| **多用户，零信任** | 完全隔离 | per-session | none | 最安全 |
| **生产环境** | 严格隔离 | per-session | none | 安全优先 |

---

## 🎯 总结：你的场景应该这样配置

**如果你的场景是**：
> "一个用户可以开启多个对话"

**我的推荐**：

### 推荐配置（平衡型）

```yaml
agents:
  defaults:
    sandbox:
      mode: "non-main"        # 主窗口免沙箱（快速）
      scope: "per-agent"      # 每个 Agent 一个容器（共享）
      workspaceAccess: "rw"   # 读写访问（方便工作）

agents:
  list:
    - name: "default"
      # 主 Agent 的配置

    - name: "experimental"
      # 实验性 Agent
      sandbox:
        scope: "per-session"  # 实验性的用独立容器
```

**逻辑解释**：

1. **主对话免沙箱**：你自己用，要快
2. **其他渠道用沙箱**：Telegram 等，要安全
3. **per-agent 共享**：
   - 同一个 Agent 的对话可以共享文件
   - 不同 Agent 隔离（比如生产 Agent vs 测试 Agent）
4. **rw 访问**：可以保存文件到项目文件夹

**实际效果**：
```
你在主窗口 (无沙箱):
  对话 1："创建 todo.txt" → 快速，直接创建

你在 Telegram (沙箱):
  对话 2："查看 todo.txt" → 容器 A，能看到
  对话 3："添加任务到 todo.txt" → 容器 A（复用），能修改

朋友的消息 (如果配置了另一个 Agent):
  对话 4："帮我做点什么" → 容器 B（隔离），看不到你的文件
```

## 🤔 特殊场景：需要完全隔离但又要共享？

**矛盾需求**：
- 每个对话独立隔离（per-session）
- 但又需要访问共同的数据

**解决方案**：

### 方案 A：只读共享 + 显式输出

```yaml
sandbox:
  scope: "per-session"
  workspaceAccess: "ro"     # 只读访问共同数据
```

然后在主对话中整理输出：
```
对话 1 (沙箱): 生成报告 → 保存到临时位置
对话 2 (主窗口): "把对话 1 的结果保存到项目" → 手动复制
```

### 方案 B：Memory 系统 + 独立容器

```yaml
sandbox:
  scope: "per-session"      # 容器隔离
  workspaceAccess: "none"   # 文件隔离
```

通过 Memory 共享结构化数据：
```
对话 1："记住分析结果：{data}"
对话 2："调用之前的分析结果" → 从 Memory 读取
```

### 方案 C：混合策略

```yaml
# 大部分对话用 per-agent（共享）
agents:
  defaults:
    sandbox:
      scope: "per-agent"

# 敏感对话用 per-session（隔离）
agents:
  list:
    - name: "sensitive"
      sandbox:
        scope: "per-session"
        workspaceAccess: "none"
```

---

**结论**：对于"一个用户，多个对话"的场景，**per-agent 通常是最佳选择**，除非你有特殊的安全需求或者每个对话确实需要完全独立。
