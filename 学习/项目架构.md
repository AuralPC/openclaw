# OpenClaw 项目架构

## 📐 整体架构概述

OpenClaw 是一个多层次、模块化的个人 AI 助手平台，采用 Monorepo 架构组织代码。

```
┌─────────────────────────────────────────────────────────────┐
│                       用户界面层                              │
│  CLI │ Gateway UI │ macOS App │ iOS App │ Android App      │
└─────────────────────────────────────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                      Gateway 控制平面                         │
│         HTTP/WebSocket Server (Hono Framework)              │
│    认证 │ 聊天 │ 定时任务 │ 状态管理 │ RPC 调用              │
└─────────────────────────────────────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                       Agent 编排层                            │
│    Agent Dock │ 工具管理 │ 位置路由 │ 白名单控制            │
└─────────────────────────────────────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                      消息渠道层                               │
│  Telegram │ Discord │ Slack │ WhatsApp │ Signal │ iMessage │
└─────────────────────────────────────────────────────────────┘
                             ↓
┌─────────────────────────────────────────────────────────────┐
│                      AI 模型层                                │
│   Anthropic (Claude) │ OpenAI │ AWS Bedrock │ 其他提供商    │
└─────────────────────────────────────────────────────────────┘
```

## 🏗️ 核心架构层次

### 1. CLI 层（命令行界面）

**职责**：用户交互的主要入口点

**关键组件**：
- [src/index.ts](../src/index.ts) - 主入口，加载环境、验证运行时
- [src/entry.ts](../src/entry.ts) - 进程重生器，处理 Node 选项
- [src/cli/program/build-program.ts](../src/cli/program/build-program.ts) - Commander.js 程序构建
- [src/cli/program/command-registry.ts](../src/cli/program/command-registry.ts) - 命令注册

**主要命令**：
- `openclaw agent` - 启动 AI 助手
- `openclaw gateway` - 启动控制平面服务器
- `openclaw message` - 发送消息到渠道
- `openclaw config` - 配置管理
- `openclaw models` - 模型管理

### 2. Gateway 层（控制平面）

**职责**：HTTP/WebSocket 服务器，统一管理所有通信

**关键组件**：
- [src/gateway/server.impl.ts](../src/gateway/server.impl.ts) - 主服务器实现
- [src/gateway/server-auth.ts](../src/gateway/server-auth.ts) - 认证子系统
- [src/gateway/server-chat.ts](../src/gateway/server-chat.ts) - 聊天子系统
- [src/gateway/server-cron.ts](../src/gateway/server-cron.ts) - 定时任务子系统
- [src/gateway/client.ts](../src/gateway/client.ts) - 客户端实现
- [src/gateway/call.ts](../src/gateway/call.ts) - RPC 调用处理

**技术栈**：
- **框架**：Hono 4.11.7（高性能 HTTP 框架）
- **WebSocket**：ws 8.19.0
- **协议**：自定义 RPC 协议

**端口管理**：
- 通过 [src/infra/ports.ts](../src/infra/ports.ts) 动态分配端口
- 支持环境变量配置

### 3. Agent 层（AI 代理编排）

**职责**：管理 AI 代理的生命周期、工具调用和任务执行

**关键组件**：
- [src/agents/dock.ts](../src/agents/dock.ts) - Agent 管理核心
- [src/agents/tools/](../src/agents/tools/) - 工具实现目录
- [src/agents/index.ts](../src/agents/index.ts) - Agent 模块导出

**核心概念**：
- **Agent Dock**：Agent 的管理容器
- **工具（Tools）**：Agent 可以调用的功能模块
- **白名单（Allowlist）**：控制哪些用户可以使用哪些工具
- **位置路由（Location Routing）**：根据地理位置路由请求

**AI 框架**：
- 基于 `@mariozechner/pi-agent-core` 0.51.3
- 支持 Agent Client Protocol (ACP)

### 4. 渠道层（消息渠道集成）

**职责**：集成多种消息平台，统一消息收发接口

**核心渠道**：

| 渠道 | 技术栈 | 目录 |
|------|--------|------|
| **Telegram** | Grammy 1.39.3 | [src/telegram/](../src/telegram/) |
| **Discord** | discord-api-types 0.38.38 | [src/discord/](../src/discord/) |
| **Slack** | @slack/bolt 4.6.0 | [src/slack/](../src/slack/) |
| **WhatsApp** | @whiskeysockets/baileys 7.0.0 | [src/web/](../src/web/) |
| **Signal** | libsignal-client | [src/signal/](../src/signal/) |
| **iMessage** | Barcelona SDK | [src/imessage/](../src/imessage/) |
| **LINE** | @line/bot-sdk 10.6.0 | [src/line/](../src/line/) |
| **Feishu** | @larksuiteoapi/node-sdk | [src/feishu/](../src/feishu/) |

**渠道抽象**：
- [src/channels/index.ts](../src/channels/index.ts) - 统一渠道接口
- 每个渠道实现入站（inbound）和出站（outbound）消息处理
- 支持媒体文件、位置、联系人等多种消息类型

### 5. 提供商层（AI 模型集成）

**职责**：集成多个 AI 模型提供商

**支持的提供商**：
- **Anthropic (Claude)** - 主要推荐
- **OpenAI**
- **AWS Bedrock**
- **Google Vertex AI**
- **Azure OpenAI**
- **其他**：Minimax、Qwen、Ollama 等

**目录**：[src/providers/](../src/providers/)

### 6. 配置层（配置管理）

**职责**：加载、验证、持久化配置

**关键组件**：
- [src/config/config.ts](../src/config/config.ts) - 配置加载器
- [src/config/types.ts](../src/config/types.ts) - 类型定义（拆分为 15+ 模块）
- [src/config/zod-schema.ts](../src/config/zod-schema.ts) - Zod 验证模式
- [src/config/validation.ts](../src/config/validation.ts) - 验证逻辑
- [src/config/io.ts](../src/config/io.ts) - 文件 I/O

**验证框架**：Zod 4.3.6

### 7. 基础设施层

**职责**：提供底层支持服务

**关键模块**：
- **日志**：[src/logging/](../src/logging/) - 结构化日志
- **媒体处理**：[src/media/](../src/media/) - 图片、PDF、音频处理
- **浏览器自动化**：[src/browser/](../src/browser/) - Playwright 集成
- **沙箱执行**：[src/sandbox/](../src/sandbox/) - 安全代码执行
- **定时任务**：[src/cron/](../src/cron/) - Cron 任务调度
- **钩子系统**：[src/hooks/](../src/hooks/) - 事件钩子

## 📊 数据流

```
用户输入
  ↓
渠道接收（Telegram/Discord/等）
  ↓
Gateway 路由
  ↓
Agent 处理
  ↓
工具调用（可选）
  ↓
AI 模型推理
  ↓
响应生成
  ↓
Gateway 分发
  ↓
渠道发送
  ↓
用户接收
```
