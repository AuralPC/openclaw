# OpenClaw AI 与 Sandbox 交互流程详解

## 🎯 核心理解

OpenClaw 的 AI 使用 Sandbox 的方式可以用一句话概括：

> **AI 通过"工具调用"（Tool Use）机制与 Sandbox 交互，AI 决定调用什么工具，系统负责路由到正确的执行环境（主机或沙箱）。**

---

## 📝 关键概念

### 1. 工具（Tool）

工具是 AI 可以调用的能力。OpenClaw 提供了多种工具：

| 工具名 | 作用 | 示例 |
|--------|------|------|
| `exec` | 执行 Shell 命令 | `ls -la`, `python script.py` |
| `read` | 读取文件内容 | 读取 `/workspace/config.json` |
| `write` | 写入文件 | 创建 `/workspace/output.txt` |
| `edit` | 编辑文件 | 修改某行代码 |
| `message` | 发送消息 | 回复用户 |
| `sessions` | 管理会话 | 创建子 Agent |

### 2. 工具调用（Tool Use）

这是 AI 模型（如 Claude）的原生能力：
- AI 可以在回复中请求调用工具
- 每个工具调用有唯一的 `toolCallId`
- 工具调用包含参数（如命令、文件路径等）

### 3. 工具结果（Tool Result）

工具执行后的返回值：
- 成功：返回执行结果（如文件内容、命令输出）
- 失败：返回错误信息
- 结果会被添加到对话历史，供 AI 继续推理

## 🔄 完整交互流程

### 阶段 1：用户发送消息

```
用户："帮我查看 /workspace 目录下有哪些文件"
        ↓
OpenClaw 接收消息
        ↓
准备 Agent 会话
```

### 阶段 2：准备执行环境

```
┌─────────────────────────────────────────────────────────────┐
│ resolveSandboxContext()                                     │
│                                                             │
│ 检查配置：                                                   │
│ ├─ sandbox.mode = "non-main"?                               │
│ ├─ 当前是主会话还是其他渠道？                                │
│ └─ 是否需要沙箱隔离？                                        │
│                                                             │
│ 如果需要沙箱：                                               │
│ ├─ 确保 Docker 容器存在                                     │
│ ├─ 确定 workspace 路径                                      │
│ └─ 返回 SandboxContext                                      │
│    {                                                        │
│      containerName: "openclaw-sbx-xxx",                     │
│      workspaceDir: "/workspace",                            │
│      enabled: true                                          │
│    }                                                        │
└─────────────────────────────────────────────────────────────┘
```

### 阶段 3：创建工具集

```
┌─────────────────────────────────────────────────────────────┐
│ createOpenClawCodingTools(sandboxContext)                   │
│                                                             │
│ 根据沙箱状态创建不同的工具：                                  │
│                                                             │
│ 如果 sandbox.enabled = true:                                │
│ ┌─────────────────────────────────────────────────────┐    │
│ │ createSandboxedReadTool(sandboxRoot)                │    │
│ │   → 读取文件时，路径被限制在 sandbox 内              │    │
│ │   → 会验证路径不能逃逸出 /workspace                  │    │
│ │                                                     │    │
│ │ createSandboxedWriteTool(sandboxRoot)               │    │
│ │   → 写入文件时，只能写到 sandbox 内                  │    │
│ │                                                     │    │
│ │ createExecTool({sandbox: sandboxContext})           │    │
│ │   → 执行命令时，会在 Docker 容器内执行               │    │
│ └─────────────────────────────────────────────────────┘    │
│                                                             │
│ 如果 sandbox.enabled = false:                               │
│ ┌─────────────────────────────────────────────────────┐    │
│ │ createReadTool(workspaceDir)                        │    │
│ │   → 直接在主机上读取文件                             │    │
│ │                                                     │    │
│ │ createWriteTool(workspaceDir)                       │    │
│ │   → 直接在主机上写入文件                             │    │
│ │                                                     │    │
│ │ createExecTool({host: "gateway"})                   │    │
│ │   → 直接在主机上执行命令                             │    │
│ └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

                            ↓

### 阶段 5：工具路由和执行

```
┌─────────────────────────────────────────────────────────────┐
│ 收到 tool_use: exec                                         │
│                                                             │
│ 1. 解析工具调用                                              │
│    toolName: "exec"                                         │
│    toolCallId: "tool_call_001"                              │
│    args: {command: "ls -la /workspace"}                     │
│                                                             │
│ 2. 路由决策                                                  │
│    ┌─────────────────────────────────────────────────┐     │
│    │ 检查执行主机（host）：                           │     │
│    │                                                 │     │
│    │ 是特权/提升命令？                                │     │
│    │   → 是：强制使用 "gateway"（主机执行）           │     │
│    │   → 否：继续检查                                │     │
│    │                                                 │     │
│    │ 配置的默认主机是？                               │     │
│    │   → "sandbox"：使用 Docker 容器                 │     │
│    │   → "gateway"：使用主机                         │     │
│    │                                                 │     │
│    │ 最终决定：host = "sandbox"                      │     │
│    └─────────────────────────────────────────────────┘     │
│                                                             │
│ 3. 构建执行命令                                              │
│    因为 host = "sandbox"，调用 buildDockerExecArgs()        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ buildDockerExecArgs()                                       │
│                                                             │
│ 输入：                                                       │
│   containerName: "openclaw-sbx-xxx"                         │
│   command: "ls -la /workspace"                              │
│   workdir: "/workspace"                                     │
│   env: {PATH: "...", HOME: "/home/sandbox", ...}            │
│                                                             │
│ 输出：Docker 执行参数                                        │
│   ["exec", "-i",                                            │
│    "-e", "PATH=...",                                        │
│    "-e", "HOME=/home/sandbox",                              │
│    "-w", "/workspace",                                      │
│    "openclaw-sbx-xxx",                                      │
│    "sh", "-lc", "ls -la /workspace"]                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 实际执行                                                     │
│                                                             │
│ spawn("docker", [                                           │
│   "exec", "-i",                                             │
│   "-e", "PATH=...",                                         │
│   "-w", "/workspace",                                       │
│   "openclaw-sbx-xxx",                                       │
│   "sh", "-lc", "ls -la /workspace"                          │
│ ])                                                          │
│                                                             │
│ 等价于在终端执行：                                           │
│ $ docker exec -i -w /workspace openclaw-sbx-xxx \           │
│     sh -lc "ls -la /workspace"                              │
│                                                             │
│ 执行结果：                                                   │
│ total 24                                                    │
│ drwxr-xr-x 3 sandbox sandbox 4096 Feb  6 10:00 .            │
│ -rw-r--r-- 1 sandbox sandbox  123 Feb  6 10:00 script.py    │
│ -rw-r--r-- 1 sandbox sandbox  456 Feb  6 10:00 data.csv     │
└─────────────────────────────────────────────────────────────┘
```

## 🔍 文件读取流程详解

当 AI 决定读取文件时：

```
┌─────────────────────────────────────────────────────────────┐
│ AI 请求读取文件                                              │
│                                                             │
│ tool_use: {                                                 │
│   name: "read",                                             │
│   input: {                                                  │
│     file_path: "/workspace/script.py"                       │
│   }                                                         │
│ }                                                           │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 沙箱路径验证                                                 │
│                                                             │
│ assertSandboxPath({                                         │
│   filePath: "/workspace/script.py",                         │
│   cwd: "/workspace",                                        │
│   root: "/workspace"                                        │
│ })                                                          │
│                                                             │
│ 检查：                                                       │
│ ✅ 路径在 /workspace 内                                      │
│ ✅ 没有 ../../../ 等逃逸尝试                                 │
│ ✅ 解析符号链接后仍在 sandbox 内                             │
│                                                             │
│ 如果路径是 "/workspace/../etc/passwd"：                      │
│ ❌ 拒绝！路径逃逸出 sandbox                                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 执行读取                                                     │
│                                                             │
│ 如果在沙箱内：                                               │
│   实际读取的是 Docker 容器内的文件                            │
│   通过 docker exec cat 或挂载卷的方式                        │
│                                                             │
│ 如果不在沙箱：                                               │
│   直接用 Node.js fs.readFile() 读取主机文件                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│ 返回文件内容                                                 │
│                                                             │
│ tool_result: {                                              │
│   content: "#!/usr/bin/env python3\n\ndef main():\n..."     │
│ }                                                           │
│                                                             │
│ AI 看到文件内容，可以继续分析、修改等操作                     │
└─────────────────────────────────────────────────────────────┘
```

## 🔐 安全机制

### 1. 路径隔离

```
┌─────────────────────────────────────────────────────────────┐
│ 沙箱路径验证                                                 │
│                                                             │
│ 用户请求读取："/workspace/../../../etc/passwd"               │
│                                                             │
│ assertSandboxPath() 检查：                                   │
│ 1. 解析路径：realpath("/workspace/../../../etc/passwd")      │
│    → "/etc/passwd"                                          │
│ 2. 检查是否在 sandbox root 内：                              │
│    "/etc/passwd".startsWith("/workspace") → false           │
│ 3. 拒绝访问！                                                │
│                                                             │
│ 返回错误：                                                   │
│ "Error: Path /etc/passwd is outside sandbox root"           │
└─────────────────────────────────────────────────────────────┘
```

### 2. 环境变量过滤

```
┌─────────────────────────────────────────────────────────────┐
│ 危险环境变量黑名单                                           │
│                                                             │
│ 在主机执行时，会过滤这些环境变量：                            │
│                                                             │
│ - LD_PRELOAD, LD_LIBRARY_PATH    → 代码注入                 │
│ - DYLD_INSERT_LIBRARIES          → macOS 代码注入           │
│ - NODE_OPTIONS, NODE_PATH        → Node.js 注入             │
│ - PYTHONPATH, PYTHONHOME         → Python 注入              │
│ - RUBYLIB, PERL5LIB              → 脚本语言注入             │
│ - BASH_ENV, ENV                  → Shell 注入               │
│ - GCONV_PATH, IFS                → 系统级注入               │
│                                                             │
│ 这些变量即使在环境中存在，也不会传递给执行的命令              │
└─────────────────────────────────────────────────────────────┘
```

### 3. 工具策略

```
┌─────────────────────────────────────────────────────────────┐
│ 工具允许/拒绝策略                                            │
│                                                             │
│ 配置：                                                       │
│ tools:                                                      │
│   allow:                                                    │
│     - "exec"                                                │
│     - "read"                                                │
│     - "write"                                               │
│   deny:                                                     │
│     - "gateway"      # 禁止直接操作网关                      │
│     - "cron"         # 禁止定时任务                          │
│                                                             │
│ 检查顺序：                                                   │
│ 1. 先检查 deny 列表（黑名单优先）                            │
│ 2. 再检查 allow 列表                                         │
│ 3. 不在列表中 → 使用默认策略                                 │
└─────────────────────────────────────────────────────────────┘
```

## 🎯 关键理解点

### 1. AI 不直接访问 Sandbox

```
❌ 错误理解：AI 直接连接到 Docker 容器读写文件

✅ 正确理解：
   AI → 请求调用工具 → OpenClaw 路由 → 执行 → 返回结果 → AI

   AI 只是发出"意图"，实际执行由 OpenClaw 系统完成
```

### 2. 工具结果是 AI 的"眼睛"

```
AI 本身看不到文件系统、看不到命令输出

AI 通过工具调用的结果"看到"这些信息：
- read 工具返回文件内容 → AI 看到文件内容
- exec 工具返回命令输出 → AI 看到命令结果
- 错误信息返回 → AI 知道出了什么问题
```

### 3. 每次工具调用都是独立的

```
工具调用不保持状态（除了文件系统状态）

例如：
- 调用 exec "cd /tmp" → 成功
- 再调用 exec "ls" → 仍在 /workspace，不是 /tmp！

因为每次 exec 都是独立的 docker exec 调用
如果需要在特定目录执行，要用：
  exec "cd /tmp && ls"
或者：
  exec {command: "ls", workdir: "/tmp"}
```

### 4. 沙箱状态在会话间可能共享

```
取决于 sandbox.scope 配置：

per-session: 每个会话独立的容器
per-agent:   同一 Agent 的会话共享容器
shared:      所有会话共享容器

如果共享，上一个会话创建的文件，下一个会话能看到
```

## 💡 总结

```
┌─────────────────────────────────────────────────────────────┐
│                    核心工作流程                              │
│                                                             │
│  用户消息                                                    │
│      ↓                                                      │
│  准备 Agent 会话 + 沙箱上下文                                │
│      ↓                                                      │
│  创建工具集（根据沙箱状态）                                   │
│      ↓                                                      │
│  发送到 AI 模型（Claude）                                    │
│      ↓                                                      │
│  AI 返回：文本 或 工具调用                                   │
│      ↓                                                      │
│  如果是工具调用：                                            │
│      ├─ 路由决策（沙箱 vs 主机）                             │
│      ├─ 执行工具（Docker exec 或 直接执行）                  │
│      ├─ 返回结果给 AI                                       │
│      └─ 循环，直到 AI 返回 end_turn                          │
│      ↓                                                      │
│  最终回复返回给用户                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘

关键点：
1. AI 通过"工具调用"与系统交互
2. 工具调用被路由到沙箱或主机执行
3. 结果返回给 AI 继续推理
4. 安全通过路径验证、环境过滤、策略控制保障
```
