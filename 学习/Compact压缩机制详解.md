# OpenClaw Compact 压缩机制详解

## 概述

当对话历史过长，接近 AI 模型的上下文窗口限制时，OpenClaw 会自动触发 Compact（压缩）机制。本文档详细分析 Compact 的完整实现，包括 JSONL 写入机制、滑动窗口、历史摘要生成等核心组件。

---

## 1. 为什么需要 Compact？

### 1.1 上下文窗口限制

```
┌─────────────────────────────────────────────────────────────┐
│                   上下文窗口问题                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   AI 模型的上下文窗口是有限的：                              │
│   - Claude: ~200K tokens                                   │
│   - GPT-4: ~128K tokens                                    │
│                                                             │
│   长对话会不断累积：                                         │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ T0 (系统提示)     : ~10K tokens                     │  │
│   │ 历史消息 (100轮)  : ~80K tokens                     │  │
│   │ 新消息 + 预留     : ~10K tokens                     │  │
│   │ ─────────────────────────────────                   │  │
│   │ 总计              : ~100K tokens                    │  │
│   └─────────────────────────────────────────────────────┘  │
│                                                             │
│   如果不压缩：                                               │
│   ❌ 超出上下文限制 → API 报错                              │
│   ❌ 响应变慢（处理大量历史）                                │
│   ❌ API 成本增加（按 token 计费）                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Compact 的目标

```
Compact 的核心目标：
┌────────────────────────────────────────────────────────────┐
│ ✅ 减少 token 数量，保持在上下文窗口内                      │
│ ✅ 保留关键信息，不丢失重要上下文                           │
│ ✅ 保持最近对话的完整性（滑动窗口）                         │
│ ✅ 自动触发，无需用户干预                                   │
└────────────────────────────────────────────────────────────┘
```

## 2. Compact 的两大组成部分

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│              Compact = 滑动窗口 + 历史摘要                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   原始 JSONL（100+ 条消息）：                                │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ m1, m2, m3, ... m85, m86, m87, m88, m89, m90, ... m100│  │
│   └─────────────────────────────────────────────────────┘  │
│                    ↓                      ↓                 │
│            ┌─────────────┐        ┌─────────────┐          │
│            │  早期消息   │        │  最近消息   │          │
│            │  (m1-m85)   │        │ (m86-m100)  │          │
│            └─────────────┘        └─────────────┘          │
│                    ↓                      ↓                 │
│            ┌─────────────┐        ┌─────────────┐          │
│            │  历史摘要   │        │  滑动窗口   │          │
│            │ (AI 生成)   │        │ (完整保留)  │          │
│            │ ~2K tokens  │        │ ~15K tokens │          │
│            └─────────────┘        └─────────────┘          │
│                    ↓                      ↓                 │
│   压缩后 JSONL：                                            │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ [摘要], m86, m87, m88, m89, m90, ... m100            │  │
│   └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 两种机制的对比

| 机制 | 处理方式 | 信息保留度 | 实现复杂度 |
|------|---------|-----------|-----------|
| **滑动窗口** | 直接保留最近 N 条消息 | 100%（原文） | 简单（机械执行） |
| **历史摘要** | AI 生成摘要 | ~20%（压缩） | 复杂（需要 AI） |

## 3. 滑动窗口机制

### 3.1 基本原理

```
滑动窗口 = 保留最近的完整消息，不做任何压缩

┌─────────────────────────────────────────────────────────────┐
│                    滑动窗口示意图                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   时间 →                                                    │
│   ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐     │
│   │ m1 │ m2 │ m3 │ m4 │ m5 │ m6 │ m7 │ m8 │ m9 │m10 │     │
│   └────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘     │
│   │←────── 压缩区域 ───────→│←─── 滑动窗口 ───→│          │
│                                                             │
│   新消息 m11 加入后：                                       │
│   ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐│
│   │ m1 │ m2 │ m3 │ m4 │ m5 │ m6 │ m7 │ m8 │ m9 │m10 │m11 ││
│   └────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘│
│   │←────── 压缩区域 ────────────→│←── 滑动窗口 ──→│       │
│                                    ↑                        │
│                              窗口向右滑动                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 窗口大小的计算

```typescript
// Safeguard 模式的窗口计算逻辑（伪代码）

// 配置参数
const contextWindow = 200000;        // AI 模型的上下文窗口
const t0Size = 10000;                // 系统提示词占用
const reserveTokensFloor = 9000;     // 预留给新内容的空间
const maxHistoryShare = 0.5;         // 历史最多占可用空间的 50%

// 计算可用空间
const availableTokens = contextWindow - t0Size - reserveTokensFloor;
// availableTokens = 200000 - 10000 - 9000 = 181000

// 计算历史配额
const historyBudget = availableTokens * maxHistoryShare;
// historyBudget = 181000 * 0.5 = 90500

// 从最新消息往回累加，直到达到配额
let keptTokens = 0;
let firstKeptIndex = messages.length;

for (let i = messages.length - 1; i >= 0; i--) {
  const msgTokens = countTokens(messages[i]);
  if (keptTokens + msgTokens > historyBudget) {
    break;
  }
  keptTokens += msgTokens;
  firstKeptIndex = i;
}

// firstKeptIndex 之后的消息 = 滑动窗口（完整保留）
// firstKeptIndex 之前的消息 = 需要压缩的部分
```

### 3.3 为什么需要滑动窗口？

```
┌────────────────────────────────────────────────────────────┐
│ 场景：用户正在和 AI 协作完成一个任务                        │
├────────────────────────────────────────────────────────────┤
│                                                            │
│ 最近的对话：                                               │
│ ┌────────────────────────────────────────────────────────┐│
│ │ User: "把 src/index.ts 里的 foo 函数改成 bar"          ││
│ │ AI: "好的，让我先看看这个文件"                          ││
│ │ [Tool: read] src/index.ts 的内容...                    ││
│ │ AI: "我看到了 foo 函数，现在修改它"                     ││
│ │ [Tool: edit] 修改 foo → bar                            ││
│ │ AI: "已修改完成，需要我运行测试吗？"                    ││
│ │ User: "好的，运行测试"                                  ││
│ └────────────────────────────────────────────────────────┘│
│                                                            │
│ 如果只有摘要，没有滑动窗口：                                │
│ ┌────────────────────────────────────────────────────────┐│
│ │ [摘要] 用户修改了 src/index.ts 中的函数名               ││
│ │ User: "好的，运行测试"                                  ││
│ └────────────────────────────────────────────────────────┘│
│                                                            │
│ 问题：                                                     │
│ ❌ AI 不知道具体改了什么                                   │
│ ❌ 工具调用的结果丢失了                                    │
│ ❌ AI 可能会问"运行什么测试？"                             │
│                                                            │
│ 有滑动窗口：                                               │
│ ✅ 最近的完整对话保留                                      │
│ ✅ 工具调用结果完整                                        │
│ ✅ AI 能正确理解上下文                                     │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 5. JSONL 写入机制

### 5.1 写入流程

```
┌─────────────────────────────────────────────────────────────┐
│                    JSONL 写入流程                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   消息产生                                                  │
│       ↓                                                     │
│   SessionManager.appendMessage()                            │
│       ↓                                                     │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ SessionToolResultGuard (包装器)                      │  │
│   │                                                     │  │
│   │  消息类型判断：                                      │  │
│   │  ├── user 消息      → 立即写入 JSONL               │  │
│   │  ├── assistant 消息 → 记录 tool_calls ID           │  │
│   │  │                    → 立即写入 JSONL               │  │
│   │  ├── tool 消息      → 立即写入 JSONL               │  │
│   │  │                    → 从 pending 移除对应 ID      │  │
│   │  └── 其他           → 立即写入 JSONL               │  │
│   └─────────────────────────────────────────────────────┘  │
│       ↓                                                     │
│   originalAppend() → 追加一行 JSON 到文件                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 关键函数

| 函数 | 来源 | 作用 |
|------|------|------|
| `SessionManager.appendMessage()` | pi-coding-agent | 核心写入方法 |
| `SessionToolResultGuard` | session-tool-result-guard.ts | 包装器，处理工具结果 |
| `flushPendingToolResults()` | 同上 | 刷新未完成的工具结果 |

### 5.3 工具结果的特殊处理

```typescript
// 为什么需要 SessionToolResultGuard？

// 场景：AI 调用了工具，但结果还没返回
// assistant 消息已写入 JSONL，但 tool 消息还没有

// Claude API 要求：assistant → tool 必须配对
// 如果缺少 tool 消息，API 会报错

// 解决方案：合成工具结果
const flushPendingToolResults = () => {
  if (pending.size === 0) return;

  for (const [id, name] of pending.entries()) {
    // 创建合成的空结果
    const synthetic = {
      role: "tool",
      tool_call_id: id,
      content: "[Tool result not available]"
    };
    // 写入 JSONL
    originalAppend(synthetic);
  }
  pending.clear();
};

// Flush 触发时机：
// 1. 新的 assistant 消息来临时
// 2. 运行结束时（finally 块）
// 3. Compact 压缩前
```

## 6. Compact 完整流程

### 6.1 触发条件

```
┌─────────────────────────────────────────────────────────────┐
│                   Compact 触发条件                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   两阶段触发机制：                                          │
│                                                             │
│   阶段一：Memory Flush（内存刷新）                          │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ 触发条件：                                           │  │
│   │   tokens >= contextWindow - reserveTokens - softThreshold │
│   │                                                     │  │
│   │ 默认值（Claude 200K）：                              │  │
│   │   tokens >= 200000 - 9000 - 4000 = 187000          │  │
│   │                                                     │  │
│   │ 执行内容：                                           │  │
│   │   AI 将重要信息保存到 memory/*.md 文件              │  │
│   └─────────────────────────────────────────────────────┘  │
│                           ↓                                 │
│   阶段二：Auto-Compaction（自动压缩）                       │
│   ┌─────────────────────────────────────────────────────┐  │
│   │ 触发条件：                                           │  │
│   │   API 返回 "context overflow" 错误                  │  │
│   │                                                     │  │
│   │ 执行内容：                                           │  │
│   │   1. 计算滑动窗口分割点                              │  │
│   │   2. 生成历史摘要                                    │  │
│   │   3. 重写 JSONL                                     │  │
│   │   4. 重试原请求                                      │  │
│   └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 完整执行流程

```
触发 Compact
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 1：刷新待处理的工具结果                                 │
│ ─────────────────────────────────────────────────────────  │
│ flushPendingToolResults()                                  │
│ - 确保 JSONL 中的 assistant/tool 配对完整                  │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 2：计算分割点（滑动窗口起点）                           │
│ ─────────────────────────────────────────────────────────  │
│ - 计算可用的历史配额（tokens）                              │
│ - 从最新消息往回累加 token                                 │
│ - 找到 firstKeptEntryId                                    │
│                                                             │
│ 结果：                                                      │
│   messagesToSummarize = messages[0 : firstKeptEntryId]     │
│   keptMessages = messages[firstKeptEntryId : end]          │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 3：收集元数据（Safeguard 模式）                         │
│ ─────────────────────────────────────────────────────────  │
│ computeFileLists(fileOps):                                 │
│   - readFiles: 读取过的文件列表                            │
│   - modifiedFiles: 修改过的文件列表                        │
│                                                             │
│ collectToolFailures(messages):                             │
│   - 失败的工具调用列表                                     │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 4：生成历史摘要                                         │
│ ─────────────────────────────────────────────────────────  │
│ summarizeInStages({                                        │
│   messages: messagesToSummarize,                           │
│   customInstructions: "请生成摘要...",                     │
│   previousSummary: 之前的摘要（如果有）                     │
│ })                                                          │
│                                                             │
│ 调用 AI API 生成摘要                                       │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 5：组装最终摘要                                         │
│ ─────────────────────────────────────────────────────────  │
│ finalSummary = historySummary                              │
│              + toolFailureSection                          │
│              + fileOpsSummary                              │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 6：重写 JSONL                                          │
│ ─────────────────────────────────────────────────────────  │
│ session.compact() 内部：                                   │
│   1. 删除 firstKeptEntryId 之前的所有消息                  │
│   2. 在开头插入摘要消息                                    │
│   3. 保留 keptMessages（滑动窗口）                         │
│   4. 覆盖写入 JSONL 文件                                   │
│                                                             │
│ ⚠️ 注意：直接覆盖，无备份！                                 │
└─────────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────────┐
│ 步骤 7：重试原请求                                          │
│ ─────────────────────────────────────────────────────────  │
│ 压缩后上下文变小，重新发送原来的请求                        │
│ 如果仍然超限 → 标记 compaction failure                     │
└─────────────────────────────────────────────────────────────┘
```

## 7. 配置选项

### 7.1 配置结构

```json
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "safeguard",
        "maxHistoryShare": 0.5,
        "reserveTokensFloor": 9000,
        "memoryFlush": {
          "enabled": true,
          "softThresholdTokens": 4000,
          "prompt": "Pre-compaction memory flush...",
          "systemPrompt": "Pre-compaction memory flush turn..."
        }
      }
    }
  }
}
```

### 7.2 配置参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `mode` | "safeguard" | 压缩模式：safeguard（高级）或 default（简单） |
| `maxHistoryShare` | 0.5 | 历史消息最多占可用上下文的比例 |
| `reserveTokensFloor` | 9000 | 为新内容预留的最少 token 数 |
| `memoryFlush.enabled` | true | 是否启用内存刷新 |
| `memoryFlush.softThresholdTokens` | 4000 | 内存刷新的软阈值 |

### 7.3 两种压缩模式

| 模式 | 特点 | 适用场景 |
|------|------|---------|
| **safeguard** | 分阶段摘要、收集文件操作、记录工具失败 | 默认，推荐 |
| **default** | 简单的单次摘要 | 简单场景 |

## 8. 注意事项和坑点

### 8.1 无备份机制

```
⚠️ 重要警告：Compact 直接覆盖 JSONL，无备份！

┌────────────────────────────────────────────────────────────┐
│ 影响：                                                     │
│ - 被压缩的原始消息永久丢失                                 │
│ - 如果摘要质量差，上下文信息会丢失                         │
│ - 无法回滚到压缩前的状态                                   │
│                                                            │
│ 建议：                                                     │
│ - 如果需要保留完整历史，在外部备份 JSONL 文件              │
│ - 关键对话考虑导出或保存                                   │
└────────────────────────────────────────────────────────────┘
```

### 8.2 摘要质量依赖 AI

```
┌────────────────────────────────────────────────────────────┐
│ 摘要质量取决于 AI 的理解能力                                │
├────────────────────────────────────────────────────────────┤
│                                                            │
│ 可能的问题：                                               │
│ - AI 遗漏了重要细节                                        │
│ - AI 误解了上下文                                          │
│ - 摘要过于简略                                             │
│                                                            │
│ Safeguard 模式的缓解措施：                                 │
│ ✅ 自动收集文件操作列表（不依赖 AI 记忆）                  │
│ ✅ 自动记录工具失败（不依赖 AI 记忆）                      │
│ ✅ 分阶段摘要，减少单次压缩量                              │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 8.3 压缩时机不可控

```
┌────────────────────────────────────────────────────────────┐
│ Compact 是自动触发的，用户无法精确控制                      │
├────────────────────────────────────────────────────────────┤
│                                                            │
│ 触发时机：上下文溢出时                                     │
│ 无法禁用：只能通过调高阈值来延迟                           │
│                                                            │
│ 可能的影响：                                               │
│ - 正在进行复杂任务时触发压缩                               │
│ - 压缩可能打断当前工作流                                   │
│                                                            │
│ 手动触发：                                                 │
│ - 可以使用 /compact 命令手动触发                           │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 9. 总结

### 9.1 核心要点

```
┌─────────────────────────────────────────────────────────────┐
│                    Compact 机制总结                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Compact = 滑动窗口 + 历史摘要                             │
│                                                             │
│   滑动窗口：                                                │
│   - 保留最近 N 条完整消息                                  │
│   - 机械执行，100% 保留原文                                │
│   - 确保当前任务上下文完整                                 │
│                                                             │
│   历史摘要：                                                │
│   - AI 生成早期对话的摘要                                  │
│   - 压缩比高，但会丢失细节                                 │
│   - Safeguard 模式自动收集文件/工具信息                    │
│                                                             │
│   JSONL 写入：                                              │
│   - 即时写入，每条消息一行                                 │
│   - 压缩时直接覆盖，无备份                                 │
│                                                             │
│   触发条件：                                                │
│   - 阶段一：Memory Flush（tokens 接近阈值）                │
│   - 阶段二：Auto-Compact（上下文溢出错误）                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 9.2 关键流程图

```
正常对话
    ↓
消息累积 → tokens 增加
    ↓
达到 Memory Flush 阈值 (187K)
    ↓
触发 Memory Flush（AI 保存重要信息到文件）
    ↓
继续对话
    ↓
达到上下文限制 (200K)
    ↓
API 返回 context overflow 错误
    ↓
触发 Auto-Compact
    ├── 计算滑动窗口（保留最近消息）
    ├── 生成历史摘要（压缩早期消息）
    └── 重写 JSONL
    ↓
重试原请求
    ↓
继续对话（上下文已压缩）
```
