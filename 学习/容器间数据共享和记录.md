# 容器间数据共享和执行记录指南

## 🎯 核心需求分析

你可能有这些需求：

1. **记录执行内容**
   - 记录执行了什么命令
   - 记录执行的结果
   - 记录创建的文件

2. **容器间共享**
   - 容器 A 创建的文件，容器 B 可以访问
   - 多个对话之间传递数据
   - 持久化工作成果

---

## 📊 五种共享和记录方案

### 方案 1：通过主工作区共享（最简单）

#### 原理图

```
你的项目文件夹（宿主机）
    /home/user/my-project/
        ├─ script.py
        ├─ data.csv
        └─ output.txt
            ↑↓ 双向映射
┌─────────────────────────────────────┐
│ 容器 A                               │
│ /workspace/ (映射到主工作区)          │
│   ├─ script.py  ← 可读可写            │
│   ├─ data.csv                        │
│   └─ output.txt ← 创建的文件          │
└─────────────────────────────────────┘
            ↑↓ 共享
┌─────────────────────────────────────┐
│ 容器 B                               │
│ /workspace/ (同样映射到主工作区)      │
│   ├─ script.py  ← 看到同样的文件      │
│   ├─ data.csv                        │
│   └─ output.txt ← 能读取容器 A 创建的 │
└─────────────────────────────────────┘
```

#### 配置方法

```yaml
agents:
  defaults:
    sandbox:
      mode: "non-main"
      scope: "per-session"     # 即使每个对话独立容器
      workspaceAccess: "rw"    # 关键：读写访问主工作区
```

#### 工作流程

```
对话 1 (容器 A):
  用户："创建一个文件 hello.txt"
  执行：echo "Hello" > /workspace/hello.txt
  结果：文件保存到 /workspace/hello.txt
       → 实际保存到 /home/user/my-project/hello.txt

对话 2 (容器 B):
  用户："读取 hello.txt"
  执行：cat /workspace/hello.txt
  结果：能读到 "Hello"！
       → 因为容器 B 的 /workspace 也映射到同一个目录

你在主机上：
  $ ls /home/user/my-project/
  hello.txt  ← 文件持久化在这里！
```

#### 优点和缺点

**优点**：
- ✅ **最简单**：只需配置 `workspaceAccess: "rw"`
- ✅ **自动持久化**：文件自动保存到宿主机
- ✅ **完全共享**：所有容器都能访问
- ✅ **易于管理**：直接在文件浏览器中查看

**缺点**：
- ❌ **安全性降低**：容器可以修改/删除主工作区的文件
- ❌ **无隔离性**：不同对话可以互相影响
- ❌ **文件冲突**：多个容器可能同时修改同一文件

**适用场景**：
- 个人使用，完全信任
- 需要跨对话协作
- 需要持久化结果

---

### 方案 2：通过共享目录挂载（高级）

#### 原理图

```
宿主机的共享目录
    /home/user/shared-data/
        ├─ shared-file.txt
        └─ config.json
            ↑↓ 只读或读写映射
┌─────────────────────────────────────┐
│ 容器 A                               │
│ /workspace/     (独立，隔离)          │
│ /shared/        (映射到 shared-data) │
│   ├─ shared-file.txt                 │
│   └─ config.json                     │
└─────────────────────────────────────┘
            ↑↓ 共享
┌─────────────────────────────────────┐
│ 容器 B                               │
│ /workspace/     (独立，隔离)          │
│ /shared/        (映射到 shared-data) │
│   ├─ shared-file.txt                 │
│   └─ config.json                     │
└─────────────────────────────────────┘
```

#### 配置方法

```yaml
agents:
  defaults:
    sandbox:
      mode: "on"
      scope: "per-session"      # 每个对话独立
      workspaceAccess: "none"   # 工作区完全隔离
      docker:
        binds:
          # 挂载共享目录（读写）
          - "/home/user/shared-data:/shared:rw"
          # 或只读挂载
          - "/home/user/read-only-data:/data:ro"
```

#### 工作流程

```
对话 1 (容器 A):
  /workspace/ → 独立的，只有容器 A 能看到
  /shared/    → 共享的，所有容器都能访问

  执行：
    echo "private" > /workspace/private.txt   # 只有容器 A 能看到
    echo "shared" > /shared/shared.txt        # 所有容器都能看到

对话 2 (容器 B):
  /workspace/ → 独立的，只有容器 B 能看到
  /shared/    → 共享的，所有容器都能访问

  执行：
    cat /workspace/private.txt   # ❌ 找不到（在容器 A 的工作区）
    cat /shared/shared.txt        # ✅ 能读到（共享目录）
```

#### 优点和缺点

**优点**：
- ✅ **隔离 + 共享**：工作区隔离，但有共享通道
- ✅ **灵活控制**：可以多个共享目录，分别只读/读写
- ✅ **清晰边界**：明确哪些是共享的，哪些是私有的

**缺点**：
- ❌ **配置复杂**：需要手动配置挂载点
- ❌ **路径管理**：需要记住多个目录的用途

**适用场景**：
- 需要部分隔离、部分共享
- 有明确的共享数据和私有数据
- 多租户环境（每个用户有独立空间+公共资源）

### 方案 3：通过 Memory 系统共享（最优雅）

#### 原理图

```
                ┌─────────────────────┐
                │   Memory 系统        │
                │  (SQLite + Vector)  │
                │                     │
                │ - 对话历史           │
                │ - 结构化数据         │
                │ - 向量索引           │
                └─────────────────────┘
                    ↑↓      ↑↓
        ┌───────────┘        └───────────┐
        │                                │
┌───────────────┐                ┌───────────────┐
│  容器 A       │                │  容器 B       │
│               │                │               │
│ 写入 Memory:  │                │ 读取 Memory:  │
│ "key=value"   │                │ "获取 key"    │
└───────────────┘                └───────────────┘

容器完全隔离，但通过 Memory 系统通信！
```

#### 工作原理

**Memory 系统位置**：[src/memory/](../src/memory/)

**核心功能**：
1. **会话记忆**：记录对话历史
2. **键值存储**：存储结构化数据
3. **向量搜索**：相关性检索
4. **持久化**：数据保存在 SQLite 数据库

#### 使用示例

```
对话 1 (容器 A):
  用户："记住：项目名称是 MyAwesomeProject"
  AI：调用 Memory 系统
      → memory.store("project_name", "MyAwesomeProject")
  结果：数据保存到 Memory 数据库

对话 2 (容器 B - 完全独立的容器):
  用户："项目名称是什么？"
  AI：调用 Memory 系统
      → memory.retrieve("project_name")
      → 返回："MyAwesomeProject"
  响应："项目名称是 MyAwesomeProject"

容器 A 和 B 完全隔离，但通过 Memory 共享信息！
```

#### 高级功能：向量搜索

```
对话 1:
  用户："记住：我喜欢用 Python 写脚本，特别是数据分析相关的"
  → Memory 系统：
      - 保存文本
      - 生成向量嵌入（embedding）
      - 存储到向量数据库

对话 2:
  用户："有什么编程语言适合处理数据？"
  → Memory 系统：
      - 生成查询向量
      - 在数据库中搜索相似内容
      - 找到对话 1 的记录（相似度高）
  → AI："根据你之前提到的，你喜欢用 Python 做数据分析..."
```

#### 配置方法

```yaml
agents:
  defaults:
    # 启用 Memory 系统
    memory:
      enabled: true
      provider: "sqlite"  # 或 "lancedb"（需要扩展）
      path: "~/.openclaw/memory/default.db"

    sandbox:
      mode: "on"
      scope: "per-session"    # 完全隔离
      workspaceAccess: "none" # 不需要文件共享
      # Memory 系统独立于沙箱，始终可访问
```

#### 优点和缺点

**优点**：
- ✅ **完美隔离**：容器完全独立，安全性最高
- ✅ **结构化**：数据有组织，易于查询
- ✅ **智能检索**：支持向量搜索（相关性）
- ✅ **跨会话**：不依赖容器生命周期
- ✅ **API 友好**：通过 API 访问，不需要文件系统

**缺点**：
- ❌ **不适合大文件**：适合元数据，不适合存储大文件
- ❌ **需要主动调用**：AI 需要明确调用 Memory API
- ❌ **学习成本**：需要理解 Memory 系统

**适用场景**：
- 多对话上下文共享
- 知识积累和检索
- 完全隔离但需要通信的场景
- 智能助手的"长期记忆"

### 方案 4：通过日志系统记录（被动监控）

#### 原理图

```
容器 A 执行命令
    ↓
stdout + stderr
    ↓
OpenClaw 捕获输出
    ↓
┌─────────────────────────────────┐
│ 日志系统 (src/logging/)          │
│                                 │
│ - 结构化日志                     │
│ - 时间戳                        │
│ - 会话 ID                       │
│ - 命令和结果                     │
└─────────────────────────────────┘
    ↓
日志文件 (~/.openclaw/logs/)
    ├─ agent-2026-02-05.log
    ├─ gateway-2026-02-05.log
    └─ sandbox-2026-02-05.log
```

#### 配置方法

```yaml
logging:
  level: "debug"    # 详细日志
  file:
    enabled: true
    path: "~/.openclaw/logs/"
    maxSize: "10m"
    maxFiles: 7
```

#### 日志内容示例

```json
{
  "timestamp": "2026-02-05T10:30:15.123Z",
  "level": "info",
  "sessionId": "sess-abc123",
  "containerId": "openclaw-sbx-agent-default-xyz",
  "tool": "exec",
  "command": "python script.py",
  "stdout": "Hello World",
  "stderr": "",
  "exitCode": 0,
  "duration": 150
}
```

#### 查询日志

```bash
# 查看今天的沙箱执行日志
cat ~/.openclaw/logs/sandbox-2026-02-05.log

# 过滤特定会话
grep "sess-abc123" ~/.openclaw/logs/*.log

# 查找执行失败的命令
grep '"exitCode":[^0]' ~/.openclaw/logs/*.log
```

#### 优点和缺点

**优点**：
- ✅ **完整记录**：所有执行都被记录
- ✅ **被动监控**：不需要主动调用
- ✅ **易于审计**：可追溯所有操作
- ✅ **故障排查**：出问题时可以查日志

**缺点**：
- ❌ **只读记录**：不能用于跨容器通信
- ❌ **文本格式**：需要解析才能使用
- ❌ **存储消耗**：详细日志占用空间

**适用场景**：
- 审计和合规
- 故障排查
- 性能分析
- 安全监控

### 方案 5：通过 Docker Volume（专业）

#### 原理图

```
Docker Volume (持久化存储)
    openclaw-shared-volume
        ├─ file1.txt
        └─ file2.txt
            ↑↓
┌─────────────────────────────────────┐
│ 容器 A                               │
│ /data → 挂载到 openclaw-shared-volume│
└─────────────────────────────────────┘
            ↑↓
┌─────────────────────────────────────┐
│ 容器 B                               │
│ /data → 挂载到 openclaw-shared-volume│
└─────────────────────────────────────┘

Volume 独立于容器生命周期，持久化存储
```

#### 创建和配置

```bash
# 1. 创建 Docker Volume
docker volume create openclaw-shared-volume

# 2. 查看 Volume
docker volume inspect openclaw-shared-volume
```

```yaml
# 3. 配置 OpenClaw
agents:
  defaults:
    sandbox:
      docker:
        volumes:
          - "openclaw-shared-volume:/data:rw"
```

#### 工作流程

```
对话 1 (容器 A):
  echo "shared" > /data/shared.txt
  → 写入 Docker Volume

容器 A 被删除（24h 后清理）
  → Volume 仍然存在！数据不丢失

对话 2 (容器 B - 新创建):
  cat /data/shared.txt
  → ✅ 能读到！即使容器 A 已删除
```

#### 优点和缺点

**优点**：
- ✅ **独立生命周期**：容器删除，数据仍在
- ✅ **高性能**：Docker 原生支持，性能好
- ✅ **易于备份**：可以备份整个 Volume
- ✅ **跨主机**：支持网络 Volume（高级）

**缺点**：
- ❌ **需要手动管理**：需要创建和删除 Volume
- ❌ **不直观**：数据在 Docker 管理的位置，不在项目文件夹
- ❌ **清理麻烦**：忘记删除会占用空间

**适用场景**：
- 需要持久化但不想暴露在主工作区
- 多容器协作的临时数据
- 需要高性能的共享存储

## 🎯 推荐组合方案

### 组合 1：个人使用（简单+有效）

```yaml
agents:
  defaults:
    sandbox:
      mode: "non-main"
      scope: "per-agent"
      workspaceAccess: "rw"   # 通过主工作区共享
    memory:
      enabled: true            # 启用 Memory 系统
logging:
  level: "info"                # 启用日志记录
```

**效果**：
- 文件通过主工作区共享（简单）
- 结构化数据通过 Memory（智能）
- 所有操作被日志记录（安全）

---

### 组合 2：多用户场景（隔离+有限共享）

```yaml
agents:
  defaults:
    sandbox:
      mode: "on"
      scope: "per-session"
      workspaceAccess: "none"   # 完全隔离
      docker:
        binds:
          # 只读共享公共资源
          - "/srv/openclaw/public:/public:ro"
          # 用户专属空间（通过变量）
          - "/srv/openclaw/users/${USER_ID}:/private:rw"
    memory:
      enabled: true              # Memory 用于跨会话通信
logging:
  level: "info"
  file:
    enabled: true
```

**效果**：
- 容器完全隔离
- 公共资源只读共享
- 每个用户有独立空间
- Memory 用于跨对话通信
- 完整审计日志

---

### 组合 3：高级开发（全功能）

```yaml
agents:
  defaults:
    sandbox:
      mode: "non-main"
      scope: "per-agent"
      workspaceAccess: "rw"
      docker:
        binds:
          - "/home/user/datasets:/datasets:ro"

          - "openclaw-shared-data:/shared:rw"

      enabled: true
      provider: "lancedb"         # 高级向量数据库
logging:
  level: "debug"
  file:
    enabled: true
    maxSize: "50m"
```

**效果**：
- 主工作区读写（开发便利）
- 数据集只读（安全）
- 缓存 Volume（性能）
- 共享 Volume（协作）
- Memory 系统（智能）
- 详细日志（调试）

## 💡 实践建议

### 建议 1：从简单开始

```yaml
# 第一阶段：只用主工作区
sandbox:
  workspaceAccess: "rw"

# 熟悉后，添加 Memory
memory:
  enabled: true

# 需要时，添加共享目录
docker:
  binds:
    - "/path/to/shared:/shared:rw"
```

### 建议 2：明确数据分类

```
临时数据（执行过程中的中间结果）
  → 容器内部，不持久化

工作成果（需要保留的文件）
  → 主工作区 (workspaceAccess: "rw")

共享资源（多个对话都需要的）
  → 共享目录或 Docker Volume

元数据和上下文（对话记忆）
  → Memory 系统

审计记录（所有操作日志）
  → 日志系统
```

### 建议 3：定期清理

```bash
# 清理闲置容器
openclaw sandbox prune

# 清理 Docker Volume
docker volume ls
docker volume rm openclaw-xxx

# 清理旧日志
find ~/.openclaw/logs -name "*.log" -mtime +7 -delete

# 清理 Memory（如果需要）
# 需要通过 Memory API 或直接操作数据库
```

## 🔍 故障排查

### 问题 1：容器间看不到文件

**原因**：
- `workspaceAccess` 设置为 `"none"`
- 或者 `scope` 设置导致使用了不同的工作区

**解决**：
```yaml
workspaceAccess: "rw"  # 改为读写
# 或
scope: "per-agent"     # 使用共享容器
```

---

### 问题 2：文件保存后容器删除就找不到了

**原因**：
- 文件保存在容器内部（`/workspace` 未映射）
- 容器删除后数据丢失

**解决**：
```yaml
workspaceAccess: "rw"  # 映射到主工作区
# 或使用 Docker Volume
docker:
  volumes:
    - "persistent-data:/data:rw"
```

---

### 问题 3：Memory 系统无法跨对话

**原因**：
- Memory 可能没有启用
- 或者使用了不同的 Memory 数据库

**解决**：
```yaml
memory:
  enabled: true
  path: "~/.openclaw/memory/default.db"  # 确保路径一致
```

## 📚 总结

### 核心答案

**Q: 有办法记录执行内容和容器间共享吗？**

**A: 有！而且有多种方式**：

1. **文件共享**：
   - 主工作区映射（最简单）
   - 共享目录挂载（灵活）
   - Docker Volume（专业）

2. **数据共享**：
   - Memory 系统（智能，推荐）
   - API 通信（高级）

3. **执行记录**：
   - 日志系统（自动）
   - 审计追踪（合规）

4. **组合使用**：
   - 根据数据类型选择不同方案
   - 文件用工作区，元数据用 Memory，审计用日志

**推荐起步方案**：
```yaml
sandbox:
  workspaceAccess: "rw"    # 文件共享
memory:
  enabled: true            # 数据共享
logging:
  level: "info"            # 执行记录
```

简单、有效、够用！ 🎯
