# 01 - 需求定义与技术选型

---

## 一、项目概述

开发一个独立的 AI 聊天前端应用，后端对接 OpenClaw，面向团队内部使用。

---

## 三、核心功能需求

### 3.1 聊天功能

- 消息流式输出（AI 回复逐字显示）
- 支持 Markdown 渲染（代码块、列表、表格等）
- 图片粘贴/上传发送
- 工具调用过程展示（可收起/展开）
- 中止回复（/stop）
- 消息排队（AI 忙碌时缓存用户输入）
- 上下文压缩提示
- 复制消息为 Markdown

### 3.2 会话管理

- 会话列表（按时间排序）
- 新建/删除/重命名会话
- 会话间切换保留各自状态
- 会话内切换模型/参数

### 3.3 用户体系（需自建）

> OpenClaw 本身没有用户注册登录系统，它的认证是设备级别的。所以**用户体系需要我们自己实现一层**，在用户和 OpenClaw 之间加一个中间层。

架构示意：

```
用户浏览器
    │
    │  HTTP（登录/注册/用户信息）
    │  WebSocket（聊天）
    ▼
我们的中间层后端（BFF）
    │
    │  管理用户账号、鉴权
    │  代理 WebSocket 连接到 OpenClaw
    │  或直接用共享 Token 连接
    ▼
OpenClaw 后端
```

两种实现思路：

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A. 轻量 BFF** | 用 Node.js/Python 搭一个薄后端，负责用户注册登录和 Token 管理，前端拿到凭证后直接连 OpenClaw WebSocket | 前端直连 OpenClaw，延迟低 | 需要处理 Token 分发逻辑 |
| **B. 全代理** | 中间层后端代理所有请求，前端不直接接触 OpenClaw | 安全性高，可做权限控制和审计 | 多一层代理，开发量稍大 |

**推荐方案 A**：内部使用，轻量 BFF 足够。

## 四、技术选型推荐

### 4.1 前端框架：Vue 3 + Vite

**推荐理由**：

| 维度 | 说明 |
|------|------|
| 上手速度 | Vue 的模板语法直观，比 React 的 JSX 更好读 |
| 开发效率 | 单文件组件（SFC）把模板、逻辑、样式放一起，改东西快 |
| 生态够用 | Vue Router（路由）、Pinia（状态管理）都是官方出品，不用纠结选型 |
| 构建工具 | Vite 本身就是 Vue 团队做的，配合最好 |
| 中文生态 | 文档、教程、社区都很友好 |
| 体量合适 | 这个项目不算特别复杂，Vue 刚好够用不过度 |

### 4.2 UI 组件库：Element Plus

**推荐理由**：

| 维度 | 说明 |
|------|------|
| 匹配度 | 专为 Vue 3 设计的组件库 |
| 内部工具适合 | 组件风格偏"管理后台"，正好适合内部工具 |
| 组件齐全 | 表单、表格、对话框、消息提示等开箱即用 |
| 深色主题 | 内置深色模式支持 |

### 4.3 样式方案：Tailwind CSS + Element Plus 主题

- Tailwind 负责自定义布局和微调
- Element Plus 负责基础组件样式
- 两者配合常见且成熟

### 4.4 状态管理：Pinia

Vue 3 官方推荐的状态管理库，轻量、TypeScript 友好。

### 4.5 中间层后端（BFF）：Node.js + Express（或 Fastify）

| 维度 | 说明 |
|------|------|
| 语言统一 | 和前端同用 TypeScript，减少上下文切换 |
| 轻量 | 只做用户认证和 Token 管理，不需要重框架 |
| 数据库 | SQLite（最简单）或 PostgreSQL（如果后续扩展） |
| 认证 | JWT Token，登录后签发，请求时带上 |

### 4.6 技术栈总览

```
┌─────────────────────────────────────────────────┐
│                   前端                           │
│  Vue 3 + Vite + TypeScript                      │
│  Element Plus（UI 组件）                         │
│  Tailwind CSS（样式辅助）                        │
│  Pinia（状态管理）                               │
│  Vue Router（路由）                              │
│  marked + DOMPurify（Markdown 渲染）             │
├─────────────────────────────────────────────────┤
│                 中间层 BFF                       │
│  Node.js + Express + TypeScript                 │
│  SQLite / PostgreSQL（用户数据）                  │
│  JWT（用户认证）                                 │
│  bcrypt（密码加密）                              │
├─────────────────────────────────────────────────┤
│                 OpenClaw 后端                    │
│  WebSocket Gateway（聊天核心）                   │
│  HTTP API（兼容端点）                            │
└─────────────────────────────────────────────────┘
```

## 六、开发阶段建议

| 阶段 | 内容 | 产出 |
|------|------|------|
| **阶段一** | BFF 搭建 + 用户注册登录 + JWT 认证 | 能注册、登录、拿到 Token |
| **阶段二** | 聊天核心 — WebSocket 连接 + 消息收发 + 流式渲染 | 能跟 AI 对话 |
| **阶段三** | 会话管理 — 会话列表、新建、切换、删除 | 多会话支持 |
| **阶段四** | 完善体验 — 工具卡片、图片上传、Markdown 美化、深色模式 | 体验打磨 |
| **阶段五** | 用户中心 — 个人信息、使用统计、偏好设置 | 功能完整 |

## 七、待讨论的问题

1. **用户体系的认证方案**：JWT 是否足够？还是需要 Session + Cookie？
2. **数据库选型**：SQLite 够用还是需要 PostgreSQL？
3. **部署方式**：Docker？直接 PM2？云服务？
4. **是否需要管理员角色**：比如管理用户、查看所有人的用量等？
5. **前端是否需要 SSR**：纯 SPA 还是需要服务端渲染（SEO 对内部工具不重要，一般不需要）？
