# OpenClaw 原型 — 后端联动功能清单

> 范围：prototype/ 目录下全部页面中**需要后端 API 支持**的功能点
> 纯前端即可实现的交互（主题切换动画、侧边栏折叠、排序、搜索过滤等）不在此列
> 生成时间：2025-02-12
> 最后更新：2025-02-12（标注后端覆盖状态 + 三层架构）

### 系统架构

```
前端（浏览器）←→ BFF（自建后端）←→ OpenClaw Gateway
```

- **前端**：只与 BFF 通信，不直连 OpenClaw
- **BFF（Backend for Frontend）**：自建中间层，负责用户系统、会话扩展属性、文件系统、消息转发等
- **OpenClaw Gateway**：AI 核心能力，BFF 通过 WebSocket 连接并转发指令

BFF 是所有消息的中转站，天然可以维护 OpenClaw 不具备的状态（用户档案、会话置顶/归档/文件夹、未读标记等）。

### 用户 → Agent → Workspace 映射

用户注册时 BFF 自动在 OpenClaw 中创建对应 Agent，并建立映射关系。每个 Agent 拥有独立的 workspace 目录。

```
BFF 用户表:
┌──────────┬──────────────┬──────────────────────────────────┐
│ user_id  │ agent_id     │ workspace_path（自动推导）          │
├──────────┼──────────────┼──────────────────────────────────┤
│ user_001 │ default      │ /openclaw-data/workspace          │
│ user_002 │ zhangsan     │ /openclaw-data/workspace-zhangsan │
│ user_003 │ lisi         │ /openclaw-data/workspace-lisi     │
└──────────┴──────────────┴──────────────────────────────────┘
```

OpenClaw workspace 隔离规则（`agent-scope.ts`）：
- 默认 Agent → `~/.openclaw/workspace`
- 非默认 Agent → `~/.openclaw/workspace-{agentId}`
- Agent 配置中指定了 `workspace` 字段 → 使用自定义路径

Docker 部署时，BFF 和 OpenClaw Gateway 挂载同一宿主机目录，使用相同 UID:GID：
```yaml
# BFF 容器
volumes:
  - /share/home/aximu1/.openclaw:/openclaw-data    # 挂载整个 .openclaw 目录
user: "1084:500"                                    # 与 gateway 相同的 UID:GID

# Gateway 容器（已有）
volumes:
  - /share/home/aximu1/.openclaw:/home/node/.openclaw
user: "1084:500"
```

BFF 直接通过 Node.js `fs` 模块读写对应用户的 workspace 目录，无需绕行 `/tools/invoke`。

## 五、文件系统模块

> **实现路径**：BFF 与 OpenClaw Gateway 容器挂载同一宿主机 `.openclaw` 目录（相同 UID:GID），BFF 通过 user→agent 映射定位到对应 Agent 的 workspace 路径，直接用 Node.js `fs` 模块操作文件系统。无需绕行 `/tools/invoke`，无文件大小限制，支持流式传输。
>
> **存储限额**：OpenClaw 对 workspace 无任何大小限制（纯文件系统目录，仅受宿主机磁盘约束）。BFF 需自建每用户存储配额机制：上传/写入前检查当前 workspace 总大小，超出限额拒绝操作并返回提示。

### 6.3 Agent 技能 `settings-skills.html` — 🔧 自建（BFF）+ 需改造 OpenClaw

> **问题**：OpenClaw 的 `skills.entries` 启禁用状态是全局的（存在 `openclaw.json`），多用户场景下会互相影响。
>
> **方案**：需要在 OpenClaw 的 `AgentConfig`（`types.agents.ts`）中新增 `disabledSkills: string[]` 黑名单字段，实现 per-agent 的技能禁用控制。
>
> - 现有白名单方案（`agents.list[].skills`）的问题：Agent 可在 chat 过程中自主创建新 skill，白名单无法覆盖后续新增的技能；且每次发送消息都要全量扫描可用技能来维护白名单，开销过大。
> - 黑名单方案（`disabledSkills`）：新技能默认可用，BFF 只需维护用户主动禁用的少量列表。OpenClaw 在 `filterSkillEntries` 环节按黑名单排除即可。
>
> **需改造 OpenClaw**（不提 PR，自行改造）：
> 1. `types.agents.ts` — `AgentConfig` 新增 `disabledSkills?: string[]`
> 2. `agents/skills/workspace.ts` — `filterSkillEntries` 增加黑名单过滤逻辑
> 3. `gateway/server-methods/agents.ts` — `agents.update` 支持修改 `disabledSkills` 字段
> 4. `commands/agents.config.ts` — `applyAgentConfig` 支持 `disabledSkills` 字段
>
> 技能**定义**仍从 OpenClaw 的 4 个来源加载（extra < bundled < managed < workspace），按 `skill.name` 去重。
> 技能**启禁用状态**由 BFF 维护 per-user 禁用列表，通过 `agents.update` 同步到对应 Agent 的 `disabledSkills` 字段，OpenClaw 在上下文注入时自动排除。

### 需新增的后端能力（按优先级）

#### 🔧 自建（BFF 层，独立开发，不依赖 OpenClaw）

| 能力 | 影响范围 | 说明 |
|------|----------|------|
| 用户注册/认证 | #1-7（7 项） | 登录、注册（含动态创建 Agent + 初始化 workspace）、忘记密码、记住我、退出登录、用户名/邮箱查重 |
| 用户→Agent 映射 | #4 关联 | 用户表维护 user_id→agent_id 映射，注册时自动创建；BFF 根据映射定位 workspace 路径、转发 WebSocket 指令到对应 Agent |
| 用户档案 | #64-68, #80（6 项） | 昵称、头像、邮箱、修改密码、主题偏好、侧边栏展示 |
| 会话扩展属性 | #26-33（8 项） | BFF 维护 session 扩展表：pinned、archived、folder、lastReadAt，实现置顶/归档/文件夹/未读 |
| Token 分布详情 | #18（1 项） | BFF 直接读取 JSONL 转录文件，按 role 分类后用 tokenizer 库分段计数 |
| 文件系统 | #48-63（16 项） | BFF 与 Gateway 挂载同一宿主机 `.openclaw` 目录（相同 UID:GID），通过 user→agent 映射定位 workspace 路径，直接 Node.js `fs` 模块操作，无大小限制 |
| 技能管理 | #75-79（5 项） | OpenClaw 技能启禁用是全局的，多用户互相影响。需改造 OpenClaw 新增 per-agent `disabledSkills` 黑名单字段；BFF 维护 per-user 禁用列表，通过 `agents.update` 同步到 `disabledSkills` 控制上下文注入 |
