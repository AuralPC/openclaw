# OpenClaw 上下文组装与对话循环机制

## 概述

本文档详细解析 OpenClaw 如何在会话启动时组装上下文，以及多轮对话中工具调用的执行循环机制。这是理解 OpenClaw AI 交互的核心内容。

---

## 1. 会话启动：上下文组装

当用户启动一个新会话（或恢复已有会话）时，OpenClaw 会组装一个完整的初始上下文发送给 AI。

### 1.1 上下文组成部分

```
┌─────────────────────────────────────────────────────────────┐
│                    初始上下文组装                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 1. 基础系统提示词（System Prompt）                      │ │
│  │    - 硬编码的 AI 行为指令                              │ │
│  │    - "You are an AI assistant..."                     │ │
│  │    - 安全规则、输出格式要求等                          │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 2. 项目上下文文件                                       │ │
│  │    - CLAUDE.md / AGENTS.md（项目开发说明）             │ │
│  │    - SOUL.md（AI 人格设定，如果存在）                  │ │
│  │    - MEMORY.md（长期记忆文件）                         │ │
│  │    - 其他 bootstrap 文件                              │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 3. Skill 列表（摘要形式）                               │ │
│  │    <available_skills>                                 │ │
│  │      - commit: 提交代码到 git                         │ │
│  │      - pr: 创建 Pull Request                         │ │
│  │      - debug: 调试代码问题                            │ │
│  │    </available_skills>                                │ │
│  │    注意：只有名称和描述，不含完整内容                   │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 4. 可用工具声明（Tools）                                │ │
│  │    内置工具：                                          │ │
│  │    - read: 读取文件                                   │ │
│  │    - write: 写入文件                                  │ │
│  │    - edit: 编辑文件                                   │ │
│  │    - exec: 执行命令                                   │ │
│  │    - glob: 文件模式匹配                               │ │
│  │    - grep: 内容搜索                                   │ │
│  │    MCP 工具（如果配置了）：                            │ │
│  │    - 来自 MCP Server 的自定义工具                     │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 5. 运行时信息                                          │ │
│  │    - 当前工作目录 (cwd)                               │ │
│  │    - 用户时区和当前时间                                │ │
│  │    - Sandbox 状态（启用/禁用）                         │ │
│  │    - 平台信息（macOS/Linux/Windows）                  │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ 6. 历史会话记录（如果是恢复会话）                        │ │
│  │    - 之前的完整对话记录                                │ │
│  │    - 或者：压缩后的摘要 + 最近 N 条消息                │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 上下文组装的代码流程

```
buildEmbeddedSystemPrompt()
├── 加载基础系统提示词
├── resolveBootstrapContextForRun()
│   ├── 查找 CLAUDE.md, AGENTS.md
│   ├── 查找 SOUL.md, MEMORY.md
│   └── 读取文件内容
├── buildWorkspaceSkillsPrompt()
│   ├── loadSkillEntries() - 从多个目录加载
│   ├── filterSkillEntries() - 过滤符合条件的
│   └── formatSkillsForPrompt() - 格式化为 Markdown
├── 收集工具声明
│   ├── 内置工具
│   └── MCP 自定义工具
├── 添加运行时信息
└── 组合成完整系统提示
        ↓
applySystemPromptOverrideToSession()
        ↓
session.agent.setSystemPrompt(prompt)
```

### 1.3 为什么 Skill 只放摘要？

```
┌────────────────────────────────────────────────────────────┐
│ 设计决策：Skill 懒加载                                      │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  方案 A：预加载所有 Skill 完整内容                          │
│  ┌──────────────────────────────────────────────────────┐ │
│  │ 优点：AI 立即可用，无需额外请求                        │ │
│  │ 缺点：                                                │ │
│  │   - 50+ Skill × 平均 500 tokens = 25000+ tokens      │ │
│  │   - 大部分对话只用到 0-1 个 Skill                     │ │
│  │   - 严重浪费上下文空间和 API 成本                      │ │
│  └──────────────────────────────────────────────────────┘ │
│                                                            │
│  方案 B：懒加载（OpenClaw 采用）                            │
│  ┌──────────────────────────────────────────────────────┐ │
│  │ 初始只放列表：~500 tokens                             │ │
│  │ AI 判断需要哪个 Skill → 调用 read 工具读取            │ │
│  │ 只加载实际需要的 Skill 内容                           │ │
│  │                                                      │ │
│  │ 优点：                                                │ │
│  │   - 节省大量上下文空间                                │ │
│  │   - 按需加载，成本可控                                │ │
│  │ 缺点：                                                │ │
│  │   - 需要额外一轮交互来读取                            │ │
│  └──────────────────────────────────────────────────────┘ │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 2. 对话循环：多轮交互机制

### 2.1 核心循环流程

```
┌─────────────────────────────────────────────────────────────┐
│                      对话循环                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    ┌──────────────┐                        │
│                    │  用户输入    │                        │
│                    └──────┬───────┘                        │
│                           ↓                                 │
│              ┌────────────────────────┐                    │
│              │ 追加到 messages 数组    │                    │
│              │ 保存到 JSONL 文件       │                    │
│              └────────────┬───────────┘                    │
│                           ↓                                 │
│              ┌────────────────────────┐                    │
│              │   发送给 AI 模型       │                    │
│              │ (完整 messages 数组)   │                    │
│              └────────────┬───────────┘                    │
│                           ↓                                 │
│              ┌────────────────────────┐                    │
│              │     AI 生成响应        │                    │
│              └────────────┬───────────┘                    │
│                           ↓                                 │
│                 ┌─────────┴─────────┐                      │
│                 ↓                   ↓                      │
│     ┌──────────────────┐  ┌──────────────────┐            │
│     │  纯文本响应      │  │  包含工具调用    │            │
│     └────────┬─────────┘  └────────┬─────────┘            │
│              ↓                      ↓                      │
│     ┌──────────────────┐  ┌──────────────────┐            │
│     │ 显示给用户       │  │ 执行工具         │            │
│     │ 追加到历史       │  │ 获取结果         │            │
│     │ 等待下一轮输入   │  └────────┬─────────┘            │
│     └──────────────────┘           ↓                      │
│                           ┌──────────────────┐            │
│                           │ 工具结果追加到   │            │
│                           │ messages 数组    │            │
│                           └────────┬─────────┘            │
│                                    ↓                      │
│                           ┌──────────────────┐            │
│                           │ 再次发送给 AI    │ ←──┐       │
│                           └────────┬─────────┘    │       │
│                                    ↓              │       │
│                           ┌──────────────────┐    │       │
│                           │ AI 继续生成      │    │       │
│                           │ (可能再次调用    │────┘       │
│                           │  工具或输出文本) │            │
│                           └──────────────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```
│         ↓                                                   │
│  追加到 messages 数组                                       │
│  保存到 JSONL 文件                                          │

│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3. 数据持久化

### 3.1 会话文件存储位置

```
存储位置：主系统（不是 Sandbox）

~/.openclaw/
├── agents/
│   └── <agentId>/
│       └── sessions/
│           ├── sessions.json           # 会话索引
│           ├── <sessionId>.jsonl       # 会话记录
│           └── <sessionId>-topic-<topicId>.jsonl
└── skills/
    └── ... (managed skills)
```

**为什么存在主系统？**

| 存储位置 | 优点 | 缺点 |
|---------|------|------|
| **Sandbox** | 隔离性好 | 容器销毁则数据丢失 |
| **主系统** | 持久化、跨会话 | 需要额外的安全考虑 |

OpenClaw 选择主系统存储，确保：
- 会话记录不会因 Sandbox 重启而丢失
- 可以跨多个 Sandbox 实例访问同一会话
- 便于统一管理和备份

### 3.2 JSONL 文件格式

```jsonl
{"role":"system","content":"你是 AI 助手...","timestamp":1707235200000}
{"role":"user","content":"帮我提交代码","timestamp":1707235201000}
{"role":"assistant","content":"好的...","tool_calls":[...],"timestamp":1707235202000}
{"role":"tool","tool_call_id":"call_001","content":"# Commit Skill...","timestamp":1707235203000}
{"role":"assistant","content":"让我执行 git status...","tool_calls":[...],"timestamp":1707235204000}
{"role":"tool","tool_call_id":"call_002","content":"modified: src/index.ts","timestamp":1707235205000}
...
```

**JSONL 的优势：**
- 追加写入：新消息直接追加，无需重写整个文件
- 流式读取：可以逐行读取，内存占用小
- 容错性好：单行损坏不影响其他记录
- 人类可读：便于调试和排查问题

### 3.3 动态重建 vs 静态存储

一个常见的误解是：T0 系统上下文在会话启动时组装后就保存到 JSONL，之后直接从 JSONL 读取。

**实际上，OpenClaw 采用的是动态重建机制：**

```
┌─────────────────────────────────────────────────────────────┐
│          常见误解 vs 实际实现                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  误解（静态存储）：                                          │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ Session 启动时:                                     │   │
│  │   读取 CLAUDE.md + Skills + Tools                   │   │
│  │         ↓                                           │   │
│  │   组装 T0 系统提示                                   │   │
│  │         ↓                                           │   │
│  │   保存到 JSONL                                      │   │
│  │                                                     │   │
│  │ 后续每轮:                                           │   │
│  │   只从 JSONL 读取，不再访问源文件 ❌                  │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  实际（动态重建）：                                          │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 每次 API 调用时:                                    │   │
│  │   重新读取 CLAUDE.md + Skills + Tools ✅            │   │
│  │         ↓                                           │   │
│  │   重新组装 T0 系统提示                               │   │
│  │         +                                           │   │
│  │   从 JSONL 读取对话历史 (T1+)                       │   │
│  │         ↓                                           │   │
│  │   合并后发送给 AI                                   │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 JSONL 实际存储内容

**JSONL 文件只存储对话历史，不存储系统上下文：**

```
JSONL 文件内容分析：
═══════════════════════════════════════════════════════════════

✗ 不存：系统提示词（每次动态生成）
✗ 不存：工具声明（每次从代码/MCP 收集）
✗ 不存：Skill 列表（每次从目录扫描）
✗ 不存：CLAUDE.md 内容（每次从文件读取）
✗ 不存：SOUL.md 内容（每次从文件读取）
✗ 不存：运行时信息（每次动态获取）

✓ 存储：用户消息 (role: "user")
✓ 存储：AI 响应 (role: "assistant")
✓ 存储：工具调用 (tool_calls)
✓ 存储：工具结果 (role: "tool")
✓ 存储：压缩摘要（如果触发了压缩）

═══════════════════════════════════════════════════════════════

实际 JSONL 文件示例：
{"role":"user","content":"帮我提交代码","timestamp":1707235201000}
{"role":"assistant","content":"好的...","tool_calls":[...],"timestamp":1707235202000}
{"role":"tool","tool_call_id":"call_001","content":"...","timestamp":1707235203000}
...

注意：没有 role:"system" 的消息被持久化！
```

### 3.5 为什么采用动态重建？

```
┌────────────────────────────────────────────────────────────┐
│ 如果采用静态存储，会有什么问题？                             │
├────────────────────────────────────────────────────────────┤
│ 场景                        │ 静态存储的问题               │
├────────────────────────────────────────────────────────────┤
│ 你修改了 CLAUDE.md          │ 老会话看不到新规则 ❌        │
│ 你安装了新 Skill            │ 老会话没有新技能 ❌          │
│ 你更新了 SOUL.md 人格       │ AI 人格不一致 ❌             │
│ 运行时信息变化（时间、目录） │ 信息过期 ❌                  │
│ 你添加了新的 MCP 工具       │ 老会话无法使用 ❌            │
└────────────────────────────────────────────────────────────┘

动态重建的优势：
✅ 修改 CLAUDE.md → 所有会话立即生效
✅ 添加新 Skill → 所有会话立即可用
✅ 更新 SOUL.md → AI 立即改变人格
✅ 当前时间/目录 → 始终准确
✅ 新增 MCP 工具 → 立即可调用
```

```
┌──────────────────────────────────────────────────────────────┐
│                    buildEmbeddedSystemPrompt()               │
│                                                              │
│   T0 = 基础提示 + CLAUDE.md + Skills + Tools + Runtime       │
│                                                              │
│   这部分每次都动态生成，不从 JSONL 读取                       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
                               +
┌──────────────────────────────────────────────────────────────┐
│                       JSONL 文件                             │
│   ┌────────────────────────────────────────────────────┐    │
│   │ T1+: 对话历史（这才是 JSONL 存储的内容）             │    │
│   │ - 用户消息                                          │    │
│   │ - AI 响应                                           │    │
│   │ - 工具调用/结果                                     │    │
│   └────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────┘
                               │
                               ↓ 合并
┌──────────────────────────────────────────────────────────────┐
│                      发送给 AI 模型                          │
│                                                              │
│   messages = [                                               │
│     { role: "system", content: T0 },    ← 刚刚动态生成的     │
│     { role: "user", content: "..." },   ← 从 JSONL 读取      │
│     { role: "assistant", content: ...}, ← 从 JSONL 读取      │
│     ...                                                      │
│   ]                                                          │
└──────────────────────────────────────────────────────────────┘
                               │
                               ↓ AI 响应后
┌──────────────────────────────────────────────────────────────┐
│                    更新 JSONL 文件                           │
│                                                              │
│   只追加新的对话消息：                                        │
│   - 用户的新消息                                             │
│   - AI 的新响应                                              │
│   - 工具调用和结果                                           │
│                                                              │
│   不保存 T0 系统上下文（下次会重新生成）                      │
└──────────────────────────────────────────────────────────────┘
```

### 3.7 上下文压缩的范围

既然 T0 是动态生成的，那么压缩（Compact）只压缩对话历史：

```
┌─────────────────────────────────────────────────────────────┐
│                    压缩范围说明                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ T0: 系统上下文（不压缩，每次重建）                      │ │
│  │ ════════════════════════════════════════════════════ │ │
│  │ • 系统提示词        → 每次从代码生成                  │ │
│  │ • 工具声明          → 每次从代码/MCP 收集             │ │
│  │ • Skill 列表        → 每次从目录扫描                  │ │
│  │ • 项目文件          → 每次从文件读取                  │ │
│  │ • 运行时信息        → 每次动态获取                    │ │
│  │                                                      │ │
│  │ 这部分不需要压缩，因为根本没存到 JSONL 里             │ │
│  └───────────────────────────────────────────────────────┘ │
│                           ↓                                 │
│  ┌───────────────────────────────────────────────────────┐ │
│  │ T1+: 对话历史（压缩目标）                              │ │
│  │ ════════════════════════════════════════════════════ │ │
│  │ • 用户消息          → 存在 JSONL                     │ │
│  │ • AI 响应           → 存在 JSONL                     │ │
│  │ • 工具调用/结果      → 存在 JSONL                     │ │
│  │                                                      │ │
│  │ 当这部分太长时，触发压缩：                            │ │
│  │ - 生成对话摘要                                       │ │
│  │ - 保留最近 N 轮完整对话                              │ │
│  │ - 用"摘要 + 最近对话"替代完整历史                     │ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
└─────────────────────────────────────────────────────────────┘

压缩前后对比：
═══════════════════════════════════════════════════════════════
压缩前（上下文快满了）：

发送给 AI 的 messages:
[
  { role: "system", content: T0 },           // ~10K tokens（动态生成）
  { role: "user", content: "消息1" },        // ┐
  { role: "assistant", content: "..." },     // │
  ... 100+ 轮对话 ...                        // │ ~80K tokens（从 JSONL）
  { role: "user", content: "最新消息" },     // ┘
]
总计: ~90K tokens

═══════════════════════════════════════════════════════════════
压缩后：

发送给 AI 的 messages:
[
  { role: "system", content: T0 },           // ~10K tokens（仍然动态生成！）
  { role: "system", content: "[对话摘要]     // ~2K tokens（压缩后的历史）
    用户在开发电商项目..." },
  { role: "user", content: "最近的消息" },   // ┐
  { role: "assistant", content: "..." },     // │ ~5K tokens（保留最近几轮）
  ...                                        // ┘
]
总计: ~17K tokens
```

### 3.8 关键理解总结

| 内容 | 存储位置 | 读取/生成时机 |
|------|---------|--------------|
| **系统提示词** | 代码中 | 每次 API 调用时动态生成 |
| **CLAUDE.md** | 项目目录 | 每次 API 调用时重新读取 |
| **SOUL.md** | 项目目录 | 每次 API 调用时重新读取 |
| **MEMORY.md** | 项目目录 | 每次 API 调用时重新读取 |
| **Skill 列表** | skills 目录 | 每次 API 调用时重新扫描 |
| **工具声明** | 代码/MCP | 每次 API 调用时重新收集 |
| **运行时信息** | 系统状态 | 每次 API 调用时动态获取 |
| **对话历史** | JSONL 文件 | 读取已有 + 追加新消息 |

**核心理解：**
- **JSONL 是对话历史的存储**，不是完整上下文的快照
- **T0 每次都动态重建**，确保配置变更即时生效
- **这就是为什么修改 CLAUDE.md 后，AI 立刻就能看到新内容**

## 5. 关键设计总结

### 5.1 为什么每次都发送完整历史？

```
┌────────────────────────────────────────────────────────────┐
│ AI 模型的特点：无状态                                       │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  AI 模型本身不"记住"之前的对话                              │
│  每次 API 调用都是独立的                                    │
│                                                            │
│  要让 AI "记住"上下文，唯一的方法是：                       │
│  把之前的对话历史作为输入的一部分发送给它                    │
│                                                            │
│  所以：                                                     │
│  messages = [系统提示] + [历史消息] + [当前输入]            │
│                                                            │
│  AI 看到的是完整的对话记录，所以能够：                       │
│  - 理解之前的上下文                                        │
│  - 知道自己调用过哪些工具                                   │
│  - 记住用户的偏好和要求                                    │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 5.2 工具调用的本质

```
┌────────────────────────────────────────────────────────────┐
│ 工具调用 = AI 的"手"                                        │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  AI 本身只能生成文本                                        │
│  但通过工具调用，它可以：                                   │
│                                                            │
│  read  → 看到文件内容                                      │
│  write → 创建/修改文件                                     │
│  exec  → 执行系统命令                                      │
│  grep  → 搜索代码                                          │
│                                                            │
│  工具的结果会被追加到对话历史                               │
│  AI 在下一轮看到结果，可以基于结果继续行动                   │
│                                                            │
│  这就形成了一个循环：                                       │
│  思考 → 行动 → 观察 → 思考 → 行动 → ...                    │
│                                                            │
└────────────────────────────────────────────────────────────┘
```
